# Threat model (STRIDE, foundation level)

Owner: Dawit. Scope: the DCC portal and its boundary with the SSO and Postiz. Revisit at each phase gate and
before the penetration test. This is a design-level model for a public repository: it contains no live infrastructure facts.

## Assets

Control of the Group's official social accounts (publishing ability); the approval record; company separation;
the audit trail; session cookies; the Postiz API key; connected-account tokens (held by Postiz).

## Threats and controls

| #   | Threat (STRIDE)                                                           | Control today                                                                                                     | Gap / next                                                                                                                                                                                                                    |
| --- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1  | **Spoofing**: forged or replayed sign-in                                  | OIDC with PKCE, state, nonce, signature/iss/aud/exp checks; single-use login state; `email_verified` required     | MFA policy lives in the SSO (D-07)                                                                                                                                                                                            |
| T2  | **Spoofing**: stolen session cookie                                       | HttpOnly, SameSite=Lax, short idle timeout, hashed at rest, back-channel logout, `__Host-` + Secure in production | device binding not implemented                                                                                                                                                                                                |
| T3  | **Tampering**: cross-site request forgery                                 | Origin check + SameSite                                                                                           | none known                                                                                                                                                                                                                    |
| T4  | **Tampering**: approval bypass by publishing straight in Postiz           | `GovernedEngine` gate for everything DCC sends; API key only on the DCC server                                    | A Postiz _administrator_ can post directly. Controls: restrict Postiz UI access to engine admins, no end-user Postiz accounts, reconciliation job that raises an incident for any post DCC did not authorise (task W-05/H-06) |
| T5  | **Tampering**: duplicate publication on retry                             | idempotency key; unknown outcomes block blind retry                                                               | DB-backed idempotency store (Hirko)                                                                                                                                                                                           |
| T6  | **Repudiation**: "I did not approve that"                                 | audit trail with actor, time, content version                                                                     | approval events pending (Hirko)                                                                                                                                                                                               |
| T7  | **Information disclosure**: one company reads another's data              | RLS (tested), per-company permission checks, 404 not 403 for foreign records                                      | every new table needs RLS and attack tests                                                                                                                                                                                    |
| T8  | **Information disclosure**: tokens or secrets in logs, responses, browser | redaction, no tokens in `/api/me`, nothing in browser storage (verified in a real browser), id_token encrypted    | production key service (D-05)                                                                                                                                                                                                 |
| T9  | **Information disclosure**: public repository                             | `.gitignore`, CI secret scan, SECURITY.md rules, owner data kept outside Git                                      | human discipline; enable GitHub push protection                                                                                                                                                                               |
| T10 | **Denial of service**: login flood, API flood                             | throttling, readiness/liveness separation                                                                         | multi-instance rate limit store when scaled                                                                                                                                                                                   |
| T11 | **Elevation of privilege**: company admin grants themselves group rights  | policy and role-scope constraint refuse it; tested                                                                | none known                                                                                                                                                                                                                    |
| T12 | **Elevation of privilege**: privileged DB insider rewrites audit          | detectable only for partial edits                                                                                 | ship chain head off-box (D-06)                                                                                                                                                                                                |
| T13 | **Elevation of privilege**: compromised SSO client secret                 | secret only in server env; rotation procedure in DEV-CLIENT-REGISTRATION                                          | production secret handling (D-05)                                                                                                                                                                                             |
| T14 | **Supply chain**: malicious dependency, compromised Postiz image          | npm audit, Dependabot, lockfile, pinned Postiz version                                                            | image provenance review before production (Dawit, per proposal)                                                                                                                                                               |
| T15 | **Webhook abuse** (if enabled): forged status events                      | not enabled; Postiz webhooks need a public HTTPS URL                                                              | must add signature/secret verification before enabling; polling is the baseline                                                                                                                                               |
| T16 | Social platform limits or account takeover at the network                 | out of DCC's control; documented in integrations                                                                  | native 2FA and backup administrators per account (onboarding checklist)                                                                                                                                                       |
