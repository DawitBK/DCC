# Threat model (STRIDE)

Owner: Dawit. Scope: the DCC portal and its boundary with the SSO and Postiz. Reviewed at each phase gate and before the
penetration test ([review log](#review-log) at the end). This is a design-level model for a public repository: it contains no
live infrastructure facts.

## Assets

Control of the Group's official social accounts (publishing ability); the approval record; company separation;
the audit trail; session cookies; the Postiz API key; connected-account tokens (held by Postiz); the encryption key file.

## Threats and controls

| #   | Threat (STRIDE)                                                                                                     | Control today                                                                                                                                                                          | Gap / next                                                                                                                                                                                                                                                                                                                        |
| --- | ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1  | **Spoofing**: forged or replayed sign-in                                                                            | OIDC with PKCE, state, nonce, signature/iss/aud/exp checks; single-use login state; `email_verified` required; two factors required by the SSO **and** by DCC (`amr=mfa`)              | proven in a real browser against the dev SSO 2026-11-14, including DCC refusing a password-only sign-in the SSO let through; to repeat on the test server                                                                                                                                                                         |
| T2  | **Spoofing**: stolen session cookie                                                                                 | HttpOnly, SameSite=Lax, 30-minute idle timeout, hashed at rest, back-channel logout, `__Host-` + Secure in production; **sensitive actions need a sign-in under 15 minutes old** (T17) | device binding not implemented; a stolen cookie still reads and does ordinary actions until it idles out                                                                                                                                                                                                                          |
| T3  | **Tampering**: cross-site request forgery                                                                           | Origin check + SameSite; checked on the running mirror                                                                                                                                 | none known                                                                                                                                                                                                                                                                                                                        |
| T4  | **Tampering**: approval bypass by publishing straight in Postiz                                                     | `GovernedEngine` gate for everything DCC sends; API key only on the DCC server; the gate also refuses archived and disconnected accounts                                               | A Postiz _administrator_ can post directly. Controls: restrict Postiz UI access to engine admins, no end-user Postiz accounts, reconciliation job that raises an incident for any post DCC did not authorise (W-05). An edit in the same instant as a publish cannot publish unapproved text: the version is fixed in the request |
| T5  | **Tampering**: duplicate publication on retry                                                                       | idempotency key in the database (one row per item, version and channel); unknown outcomes block blind retry and are audited                                                            | a key stuck `in_progress` or `unknown` needs the reconciliation job to settle it (W-05)                                                                                                                                                                                                                                           |
| T6  | **Repudiation**: "I did not approve that"                                                                           | audit events for submit, review, approve, reject, publish, failed and unknown publish, freeze and unfreeze, with actor, time and content version                                       | none known                                                                                                                                                                                                                                                                                                                        |
| T7  | **Information disclosure**: one company reads another's data                                                        | RLS (tested), per-company permission checks, 404 not 403 for foreign records; attack tests for every module                                                                            | every new table needs RLS and attack tests (checked in review)                                                                                                                                                                                                                                                                    |
| T8  | **Information disclosure**: tokens or secrets in logs, responses, browser                                           | redaction, no tokens in `/api/me`, nothing in browser storage, id_token encrypted; production key in a file outside the repository, the environment and the backups                    | whoever reads files as the service account reads the key (accepted, ADR-0007)                                                                                                                                                                                                                                                     |
| T9  | **Information disclosure**: public repository                                                                       | `.gitignore`, CI secret scan, GitGuardian on pull requests, SECURITY.md rules, owner data kept outside Git                                                                             | human discipline; confirm GitHub push protection is on                                                                                                                                                                                                                                                                            |
| T10 | **Denial of service**: login flood, API flood                                                                       | throttling, readiness/liveness separation                                                                                                                                              | multi-instance rate limit store when scaled                                                                                                                                                                                                                                                                                       |
| T11 | **Elevation of privilege**: company admin grants themselves group rights                                            | policy and role-scope constraint refuse it; self-grant refused; tested                                                                                                                 | removing the last group administrator is not refused yet (H-08)                                                                                                                                                                                                                                                                   |
| T12 | **Elevation of privilege**: privileged DB insider rewrites audit                                                    | **audit checkpoints**: a full consistent rewrite and a removal of events are detected (tested against real PostgreSQL)                                                                 | the copy must live where the database administrators cannot write, and the daily job must exist: both need the test server (D-04). Until then the control is built but not in force                                                                                                                                               |
| T13 | **Elevation of privilege**: compromised SSO client secret                                                           | secret only in the server environment file; rotation procedure written                                                                                                                 | none known                                                                                                                                                                                                                                                                                                                        |
| T14 | **Supply chain**: malicious dependency, compromised Postiz image                                                    | npm audit (0 findings on 2026-11-14), Dependabot, lockfile, pinned Postiz version                                                                                                      | image provenance review before production (Dawit, per proposal)                                                                                                                                                                                                                                                                   |
| T15 | **Webhook abuse** (if enabled): forged status events                                                                | not enabled; Postiz webhooks need a public HTTPS URL                                                                                                                                   | must add signature/secret verification before enabling; polling is the baseline                                                                                                                                                                                                                                                   |
| T16 | Social platform limits or account takeover at the network                                                           | out of DCC's control; documented in integrations                                                                                                                                       | native 2FA and backup administrators per account (onboarding checklist)                                                                                                                                                                                                                                                           |
| T17 | **Elevation of privilege**: an unattended or hijacked session grants roles, lifts a freeze or takes the audit trail | re-authentication: those actions need a sign-in at the SSO under 15 minutes old; the SSO is asked to authenticate now and DCC checks `auth_time` is fresh (tested)                     | proven in a real browser 2026-11-14; the web app must handle the `reauth_required` answer (R-07)                                                                                                                                                                                                                                  |
| T18 | **Elevation of privilege**: a person approves their own words by editing someone else's draft                       | nobody who wrote any version of an item may review, approve or reject it (found and fixed in the review of 2026-11-13; tested)                                                         | the signed approval matrix (A-05) may add more rules                                                                                                                                                                                                                                                                              |
| T19 | **Repudiation / tampering**: a restored backup is not the database that was backed up                               | the backup manifest carries the dump's SHA-256 and the audit chain head; the restore procedure compares them                                                                           | none known                                                                                                                                                                                                                                                                                                                        |

## Review log

### 2026-11-14, gate M0 (foundation), by Dawit

Reviewed with the backend modules merged ([review](../project/reviews/2026-11-13-BACKEND-MODULES-REVIEW.md)) and the mirror
rehearsal done ([record](../devops/DEPLOYMENT-AND-ROLLBACK.md)).

- **Closed since the foundation:** T5 (database idempotency store), T6 (approval events), T8 (production key handling decided
  and built), T12 (checkpoints built and tested), T13 (rotation written). **New and closed:** T17, T18, T19.
- **Found by this review and fixed:** five findings in content, publishing and notifications (T4, T6, T18); a sign-in that
  answered 500 when the SSO was down.
- **Open critical or high findings: none in the code as built.**
- **Open, medium:** T12 is not in force until the checkpoint copy and its daily job exist on a server; T4's reconciliation job
  (W-05) does not exist. T1 and T17 were run in a real browser against the dev SSO later the same day and passed.
- **Not assessed, by design, until there is something to assess:** the Postiz deployment and its administrator access, the
  network integrations, the production server, HTTPS and the Apache route.
